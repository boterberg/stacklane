en:
  title: Locked down tighter
  label: Security
  summary: A security update after a new audit of 1.4. We recommend that everyone running Stacklane updates.
  changes:
    verbeterd:
      - A link to confirm an email address only works when you are signed in to the account the address belongs to.
      - API tokens can no longer rebuild a server, add SSH keys or pass them with an order, or attach volumes, floating IPs or networks to a server.
      - API tokens can no longer change the team. Adding someone to the team needs a confirmed email address.
      - A VAT number has to come from the same country as your address.
      - When your email address changes, Stacklane also changes it in the game panel and in VirtFusion. When you delete your account, your users there go too.
    opgelost:
      - A password change, password reset or turning on 2FA did not always stop a sign-in, new token or email change that was already under way.
      - A customer could start a server while it was being suspended.
      - On a Proxmox cluster with several connections, two customers could get the same VLAN, IP address or VM number.
      - Private networks stayed after a customer's last server on that platform was cancelled.
      - A cancelled VPS that never finished setting up stayed behind at OpenStack or VirtFusion.
      - The reverse DNS of a freed IP address could stay with the next customer.
      - Web hosting could take another customer's domain through capital letters or a subdomain.
      - Mollie renewal payments could get stuck when a webhook failed.
      - The demo no longer sends email.

# v1.4.1.0: Strakker dicht

<ReleaseMeta />

[Read this in English](/releases/en/v1.4.1.0)

Na 1.4.0.0 hebben we Stacklane opnieuw grondig laten doorlichten. Er kwam niets kritieks uit, maar wel een reeks gaten die we niet open wilden laten. Ze zijn allemaal dicht, elk met een test die controleert dat het zo blijft.

Twee dingen merk je zelf. Een link om je e-mailadres te bevestigen vraagt nu eerst om in te loggen, als je dat nog niet was. En scripts met een API-token kunnen minder dan voorheen: alles wat toegang tot een server geeft of spullen tussen servers verplaatst, doe je voortaan in het panel. De [API-gids](/guides/api) zegt precies wat wel en niet kan.

Bijwerken gaat zoals altijd met `stacklane update`. Er zitten twee kleine databasewijzigingen in, die gaan vanzelf.
